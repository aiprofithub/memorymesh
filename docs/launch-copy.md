## Hacker News post

```txt
Hey HN,

I’m building MemoryMesh, an open-source memory layer for AI agents.

The problem: most agents forget everything between sessions, or developers end up stuffing raw chat history into prompts. That does not scale well, and it gets risky when agents start handling customer, project, or team context.

MemoryMesh provides a small memory API, TypeScript SDK, and MCP server scaffold so agents can remember, search, and forget context explicitly.

The goal is not to be “just another vector database.” The goal is a memory control layer:
- explicit remember/search/forget APIs
- portable memory across models and tools
- memory types like preference, decision, task, warning, insight
- planned audit logs, retention policies, and team memory
- open-source local mode, with hosted Cloud later

Would love feedback from people building production agents:
1. What memory primitives do your agents actually need?
2. Would you rather self-host this, use a hosted endpoint, or both?
3. What would make you trust an AI memory layer?
```
